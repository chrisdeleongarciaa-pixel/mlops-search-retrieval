# Contratos ejecutables del perfil testigo

La [referencia candidata](reference/v1/CONTRATOS_Y_ENTORNO_REPRODUCIBLE_RETRIEVAL.md) conserva los bytes de la fuente y su [checksum](reference/v1/SHA256SUMS). Las siguientes cláusulas describen las fronteras implementadas. La [verificación](../verification/witness-increments.md) distingue los perfiles observados.

| ID | Operación y precondición | Postcondición e invariante observable |
| --- | --- | --- |
| SE-01 | `EventSubmission.submit_event` recibe el ámbito autorizado, un sobre v2 y un stream del conector para `UPSERT`. El sobre contiene `source_event_id`, `document_id`, `source_position`, `source_revision` y `operation`. Un alta añade `original_ref`, `original_version`, `original_size` y `original_sha256`. | El ID de fuente se compara dentro de tenant y fuente antes de decidir orden. Un reenvío equivalente resuelve el mismo resultado durable. Una posición aceptada bajo otro ID produce un descarte obsoleto persistido. El evento aceptado, el recibo y la outbox comparten transacción. La migración conserva los recibos v1. |
| SE-02 | `replay_witness` recibe un manifiesto confiable con cursores únicos y contiguos y el corpus del hash declarado. | El checkpoint, identificado por el hash del manifiesto, avanza un cursor por decisión durable. Una discontinuidad, conflicto o resultado incierto detiene el avance. El cursor se conserva separado de la identidad y el orden de origen. |
| SE-03 | El conector reenvía el mismo sobre y bytes tras una interrupción. | Antes del commit puede quedar un original sin referencia. Después del commit se recupera el mismo recibo y existe un solo evento lógico. |
| WP-01 | El worker toma un evento de outbox con una concesión vigente, verifica el original y construye el manifiesto de fragmentos UTF-8 con offsets de bytes semiabiertos. | La reserva persistida vincula cada identidad de proyección a un hash inmutable. La activación exige visibilidad por búsqueda, concesión vigente por token, generación activa y secuencia deseada. El retiro excluye las publicaciones anteriores incluso si posteriormente se acepta otra actualización. |
| WP-02 | La búsqueda obtiene del caller su tenant autorizado y un presupuesto positivo. | Aplica en el motor tenant, generación y proyecciones elegibles antes del límite. Revalida una vez y reintenta como máximo una vez si cambia el conjunto. Contexto y resultados reutilizados requieren una lectura fresca. El perfil mutable limita a 1.000 proyecciones autorizadas por defecto. |
| RB-01 | Exacto y RRF reciben representaciones compatibles y listas completas del mismo snapshot. | El exacto falla si falta un vector elegible. RRF preserva ambas listas, combina los rangos independientes y desempata por ID. |
| DL-01 a DL-07 | El transporte suministra una lectura de autoridad ligada a su principal. El backend privado se ejecuta en el perímetro autorizado. Se utiliza el chat template del modelo real para medir el prompt. | Se revalida antes de construir contexto y antes de devolver un cuerpo privado completo. Las citas deben identificar fragmentos del prompt efectivo. El público distingue tokens provisionales y estado terminal. Cerrar el stream cierra el iterador de backend y devuelve su plaza de admisión. |

La primera política local de ACL usa concesiones directas por principal y documento. El operador debe marcar cada documento privado antes de activar su proyección. La búsqueda pública excluye documentos con esa marca, incluso si el principal tiene una concesión privada. Las mutaciones de clasificación y ACL pertenecen al operador autorizado de la autoridad PostgreSQL.
